# 联席学情报告技能 · co-teacher-report

把企业微信班级群聊天 + 后台课节考勤（＋可选的小黑板手写作答图片读图），一键生成「联席 / 教务 / 课程」三视角学情报告（HTML）。

> 🧑‍🏫 **给业务同学（联席 / 教务 / 学管）：不用看下面的命令行。**
> 直接打开仓库里的 **`操作手册.html`** —— 3 步出报告，全程只用跟 WorkBuddy 说话
> （第 0 步：把**网址 + 账号密码**发过去，它会自动打开登录页并把**验证码截图发你辨认**，你回 4 位数字即可），
> 并附「报告三大 Tab 怎么看」「⚠️ 建议先跟进的学生 / 预警卡怎么用」「教务续报数据怎么读」「常见问题」。

## 一键安装（推荐）

```bash
bash <(curl -sL https://raw.githubusercontent.com/feidou-lxy/co-teacher-report/main/install.sh)
```

脚本会把技能装到 `~/.workbuddy/skills/co-teacher-report/`。
（如需指定其他仓库/分支：`REPO=https://github.com/其他账号/co-teacher-report BRANCH=main bash <(curl -sL <install.sh地址>)`）

## 使用（用你自己的后台账号）

1. 取 `x-token`（JWT，约 24 小时有效）—— **账号密码这条路最快**：
   - **方式 A（推荐）**：把**网址 + 账号密码**发给 WorkBuddy。它自动打开登录页、把账号密码填好，
     再把**图形验证码截图**发给你；你回 4 位数字，它自动提交登录并取到 `token`。
     **你不用自己开浏览器、不用按 `F12`。**
   - **方式 B（兜底）**：自己登录后按 `F12` → Console 输入 `document.cookie`，把 `token=...` 那一段**整段复制**。
   ⚠️ 两条路都**不包含**「用账号密码去调后台登录接口」——那等于让机器去过图形验证码，不稳定也不该做。
   账号密码只用于本次登录，**不会写入任何文件**（含 `token.txt` / 日志 / 报告）。
   ⚠️ 请用**自己的后台工作账号**，不要互传账号密码。
2. 写入工作目录（`token.txt` 支持「裸 token / `token=xxx` / 整段 cookie / JSON」，脚本会自动抽出真值）：
   ```bash
   mkdir -p ~/co-report && echo "粘贴你的x-token（整段复制也行）" > ~/co-report/token.txt
   ```
3. 生成报告（仅用 Python 标准库，无需第三方依赖）：
   ```bash
   # —— 新接口链路（v4.11 推荐；课程 / 联席维度）——
   # 研发已封装「在读学生」接口，直接拿到学生↔群 roomId 映射，少一层群名反查
   # ⚠️ 课程名必须是**完整全串**（接口精确匹配），从后台复制，如 2026Q-SX-高二数学清北层日E邵
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --api --fill --course 2026Q-SX-高二数学清北层日E邵 \
     --window 2026-09-01 --boards ~/Desktop/小黑板目录
   # 联席视角（跨课程）
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --api --fill --co <联席名> --window 2026-09-01 --month 2026-09

   # —— 旧链路（教务维度目前只有这条路）——
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --edu <教务名> --window 2026-09-01 --month 2026-09
   # 课程视角（旧链路，课程名可用片段）
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --course 高二数学211层六C肖 --window 2026-09-01 --boards ~/Desktop/小黑板目录

   # —— 指定「时间段」（v4.16）：起止都写，报告即按该闭区间出 ——
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --api --fill --co <联席名> --window 2026-09-15 --end 2026-09-30 --month 2026-09
   ```
4. 产物：`<联席|教务|课程名>_学情分析.html`（v3.9 起不再产出 Excel，全部结论都在报告内）

### 一、飞书表接入（v4.19 ~ v4.21）

新增三个脚本，把团队自维护的飞书 Wiki 表纳入学习证据：

| 脚本 | 作用 |
|---|---|
| `pull_feishu.py` | 双通道取数（`lark-cli` / 官方 API），宽表按块拉取，支持 `--resume` 续传 |
| `adapt_feishu.py` | 结构探测 → 契约第 8 张表 `feishuLearning.json` ＋ `feishuMeta.json` |
| `fixlist_feishu.py` | 生成「表内待补 / 待修」清单页，团队自己维护数据用 |

`detect()` 一次覆盖 **7 种表结构形态**，全部判据来自实测反推，不按列号硬编码：

1. 宽表 · 2 行表头
2. 宽表 · 3 行三维表头
3. 窄表（格内 `出勤,作业,框架笔记`，拆布尔位）
4. 续行表头 · 合并单元格（forward fill 继承）
5. 课次区中间插列（每节课插的位置还不一样）
6. 表尾公式辅助列（`columnSkipPatterns` 跳过）
7. **单行表头内联子列名**（v4.20，`第1次课-出勤` 重复出现，需按课次号合并）

元数据列**只按表头文字匹配、不按列号**（同团队内表间列序都不一致）；团队自定义叫法用
`profile.feishu.metaAlias` 覆盖，优先级高于内置别名表。v4.21 增加 `ratings` 声明，
支持 ABCD 等级抽取成**逐课趋势序列**（不声明 = 不启用）。

### 二、学习分层改为五类证据（v4.23）

原四类（小黑板 / 作业闭环 / 老师反馈 / 成绩）＋ **第 ⑤ 类：飞书表的提交情况与作业评级**。
飞书表不再作为独立小模块，而是拆成片段插进卡片不同位置（提交情况 / 需关注的点 /
评级轨迹 / 老师手记）。**v4.28 增加反向误判防护**：飞书表已确认提交时，
聊天侧「催交作业未响应」不再算问题。

### 三、学生卡片重构：一眼 + 两折（v4.27 ~ v4.38）

用户原话「每个学生情况分析的内容太长了，无法快速获取有效信息」。原来「①学习情况 /
②配合度 / ③To-Do」三块并列，读者要跨三块自己拼结论。现在：

- **一眼** = 诊断句（只做事实组合、不加形容词）＋ 四格指标（作业提交 / 出勤 / 群内发言 /
  最近活跃）＋ 学生问题（表内原句，不改写）＋ 薄弱知识点（名＋条数，点开看题型）＋ 最该做 / 其次
- **两折** = 补充信息（指标格读不出来的）／ 其余跟进建议（第 3 条起）
- 「其次」**固定可见不折叠**；「学习分层判定依据」整行**不渲染**

**出勤口径 v4.38 修正**（本轮最容易出错的一处）：购「直播」课的学生，**看直播、看回放都算出勤**，
指标格一律写**有效出勤**（`eff`），不能写纯到课数 —— 实测某生 2 节到课 + 2 节回放曾被显示成
「到课 2/5」，与同一张卡的「出勤 4/5」自相矛盾。只有「既没到课、也没看回放」才算真缺课，
缺 1 节时直接给节次（「第 5 节没看」）。全看回放但看全 = 完成，不上屏、不扣分。

### 四、教务核心数据（v4.39 ~ v4.45）

教务视角新增三项，数据来自 `snapshot/enroll.json` 与 `chats.json`：

1. **学生卡头部身份行**：在读科目（标签）＋ 续报（已续报 / 未续报）＋ 扩科意向（chip ＋
   **±25 字原文依据**）。**有内容才渲染** —— 空项不占位，避免一堆灰色「—」。
2. **Tab② 顶部「📋 教务核心数据」**：6 张可点 KPI（已续报 / 未续报·其他 / 续报未确认 /
   多科目在读 / 单科在读 / 有扩科意向）＋ 学生级明细表，纯前端联动（`data-r`/`data-m`/`data-k`）。
3. **课程筛选上移到页面顶部**（v4.41）：课程是**整体筛选维度**，点顶部「课程」标签，
   顶部 KPI、Tab②③ 全部同步；Tab②③ 内不再有独立的课程下拉（避免两个 Tab 口径打架）。

**续报字段来源**：研发接口 `getCoTeacherStudents` 的 `renewed`（"是"/"否"/"未设置"，
DB 1/2/0），由 `pull_enroll.py --edu` 在线拉取写入 `enroll.json["renew"]`。
「未设置」计入**续报未确认**（橙），是**真实业务状态**（学生未选 / 教务未填），不是接口缺失；
整批无数据时 KPI 显示「—」而非 0。

**扩科意向口径已收口**（v4.39）：提到其他科目 **＋ ±25 字内有意图词**（报名 / 想报 / 想学 /
咨询 / 加课 / 打算 / 补 / 试听…）才记，并排除 4 类噪声（招生发言人、营销话术「🔥/热报名中」、
「英语老师 / 作业」语境、「加课 / 报课」距科目 > 8 字）。证据原文落盘 `kuake.json`。

⚠️ **教务名查不到学生时**：接口按「联席姓名」过滤，教务名直查返回 `total=0`。v4.45 起
`pull_enroll.py --edu` 自动从 `roster.json` 提取全部 `coTeacherName`，逐联席拉取后按
`studentSeq` 合并去重。

### 五、薄弱点误判修正（v4.46 / v4.47）

联席反馈：「之后学导数的时候我们也会碰见」被误判成薄弱点。修了四类：

- 删过泛词（`还是有` / `巩固` / 裸 `计算`）；单个「错」改为词组（做错 / 算错 / 订正）
- **±16 字语境窗口**：附近有「之后学 / 会碰见 / 还没学 / 再讲」或「没问题 / 全对 / 没算错」→ 该处不计
- 先剥离微信引用块；「要注意」等须同句有「你 / 这道题」
- 仅 1 条提及、且无小黑板实证的知识点，从「薄弱点」行**降级到补充信息 → 群内提及**

### 七、v4.49 ~ v4.50（固定工作目录 / 轻量刷新 / 飞书「总结」/ 活跃度改学习口径）

**v4.49 · 固定工作目录**
报告不再生成在当前目录，而是固定落到 `~/.workbuddy/reports/<视角>-<姓名>[@课程]/`
（`scripts/workdir.py` 是唯一规则来源，`run_all.py` 与 `refresh.py` 共用）。
两个入口脚本的 `--workdir` 默认改为 `None`：不传就按视角自动定位并建目录，显式传路径仍兼容。
好处：`token.txt`（约 24h）可复用、快照可复用、同一对象历史只落一处、
**更新技能不会丢报告**。

**v4.49 · 轻量刷新 `scripts/refresh.py`**
只做三件事：拉 `renewed` → 就地更新 `snapshot/enroll.json` 的 `renew`/`renewDetail`
（`bySeq` 不动）→ 复用 `report.py` 重渲染（**不拉群聊、不跑 extract**）。实测 **2 秒**。
安全铁律：token 失效则退出码 2 **且不写盘**（空 `renew` 覆盖会把续报 KPI 清成 0）；
接口只返回部分学生时**合并非覆盖**；写盘 temp + `os.replace`；渲染失败不删旧 HTML。
定时任务用**系统 crontab / launchd**（模型 token 消耗 0），别用 AI 定时任务。
⚠️ 但它只改**磁盘上的 HTML**，更新的是本机那份；已经转发出去的副本不会变。
⚠️ **在 GUI 宿主里装不了系统定时任务**（`crontab` 报 `operation not permitted`、
`launchctl bootstrap` 报 `5: Input/output error`）—— 需用户在「终端」里或双击 `.command` 装。

**v4.50 · 飞书「总结」纳入完成情况**
`DEFAULT_DONE` 加入「总结」（学生课后自写的复盘，取值 `已交` / `未交` / `#N/A`）。
其中 **`佳作`** 不并入完成数，单列 `excellent` 字段，只在「作业提交」格的悬停里显示
「其中佳作 N 次」—— 它表示「写得特别好」，与「按时交了」不是一回事。

**v4.50 · 活跃度改「学习口径」（最关键）**
用户原话：「活跃的定义需要从学习的积极主动性方面去做判断，比如有的学生发了很多消息，
但是没什么学习相关的」。旧口径按**发言总量**判 → 群里闲聊刷屏的被判「积极」，
闷头做题的反而不积极。现改为只看**学习相关发言**：
`extract.py` 新增 `STUDY_KW` / `STUDY_EXCL` / `is_study_msg()`，每个学生多两个字段
`n_study`（学习相关发言条数）与 `gap_study`（最后一条学习发言距窗口末天数）。

| 顺序 | 条件 | 档 |
|---|---|---|
| 1 | 本人实质发言 0 条 | 沉默不回复 / bad |
| 2 | 有发言但 `gap_study is None`（无一条与学习相关） | **只闲聊不学习 / warn** |
| 3 | `gap_study >= 14` | 近期沉默 / bad |
| 4 | `n_study >= 8` 或主动提问 ≥3 | 积极 / ok |
| 5 | `n_study <= 2` | 不积极 / warn |
| 6 | 其余 | 一般 / warn |

四格指标随之改名：`发言数 / 最近发言` → **`学习发言 / 最近学习`**。
⚠️ 词表必须收单字「题」「课」（实测「课上的题我可能得在纸上写」）与
`classin` / `网络` / `登录` / `登不进`（实测「网络登不上 classin」曾被误判成闲聊）。
误判实测：本人实质发言里**仅约 29% 与学习相关**。

**v4.50 · 学生概览 Tab 去噪**
口径 / 校验 / 原文出处一律收进 `<details>`，没有内容的分组整组不渲染；
删掉 `kpihint`、`edu-cnote` 与「💡 点击上方任一统计卡…」整行。

### 八、v4.51（飞书备注里的成绩单列一行 / 薄弱点下钻两条路）

**① 备注里的「月考 / 分数 / 名次」→ 卡片可见区独立一行「成绩」**

用户原话：「这是娜娜团队飞书表格中【学生情况备注】……还有月考成绩或者分数相关的内容；
如果你之前已经识别了，这些也属于重要信息，需要优先展示」。

识别是有的（「学生情况备注」→ `note`，靠 `profile.json` 的 `feishu.metaAlias` 声明），
但呈现错位：「月考还可以」被 `fs_issues()` 当成**橙色问题**（语义反了），
「成绩还算稳定」「理科好文科差」没有问题词，**整句被丢弃**。

- 新增 `common.fs_score_notes(note)`：成绩 / 分数 / 名次句单独摘出，切句**一律按逗号**
  （否则「最近作业也不按时交，考的不好，家长想退费」会整句变成成绩，把前两条真问题吞掉）。
- 渲染 `report.score_row()`，位置在**四格指标下、学生问题上方**：
  绿 = 考得好 / 红 = 偏低 / 蓝 = 中性事实；能摘出数值的以角标跟随（`76 分`、`第 3 名`）。
- 与「学生问题」**互斥去重**（只剔完全相同句，不做包含 —— 「应该比较粗心，月考试卷答题卡都丢了」
  里的「粗心」不能跟着丢）。
- **不给「按 150 分制推断」的单个数字着色**：小测多为 100 分制，硬按 150 算会把 70 分判成偏低。
- 跳过「没有月考 / 月考八号九号 / 月考已经考完了」这类只讲安排、没有结论的句子。

**② 薄弱点下钻：可见区 chips ＋ 展开后完整清单**

用户反馈「之前可以下钻细分问题，最新报告里没看到了」。排查结论：**功能没坏**
（62 个 `tchip`、68 个 `tchipd` 都在），是 v4.35 把整块 `render_fine()` 换成 chips 后，
可见区只剩「薄弱点」三个字，**没有任何「可以点」的暗示**；带 🎯 标题的完整清单只在
「没有 chips」的兜底分支出现，读者自然以为没了。

- 可见区 chips 后补灰字提示 **「点知识点看题型与原文」**；
- `补充信息` 折叠区里**始终**输出完整清单，标题改为
  **「🎯 具体薄弱点 · 完整清单（与上方「薄弱点」同源；知识点 → 题型 → 原文出处）」**。
- ⚠️ 这是**刻意的双份呈现**：chips 是结论位的索引，完整清单是一次看全的明细。别再以「重复」为由删。

## 版本与口径（v4.18）—— 修正「看回放被算成未出勤」的漏判

**用户反馈**：「目前你把学生看了回放的这种，归于未出勤了；但是回放也属于出勤，你检查一下」

### 查明两处（都在真实存档上验证过）

| # | 位置 | 现象 |
|---|---|---|
| ① | `coverage.py` 的失联判定 | 读的是 `attendCount`（**纯到课数，不含回放**）→「没到课但看了回放」的学生 `learn=False`，与「群内无消息」叠加后被判成**「失联」**（本应「出勤但无沟通」） |
| ② | 教务存档的 `attendance_clean.json` | 该文件由 **v3.8 之前**的脚本产出，`absentCount` 是旧口径（总节数 − 到课数），把「已看回放补齐」的节次算成了缺课 |

> 技能代码里 `build_attendance.py` 自 v3.8 起口径就是对的（有效出勤 = 到课 + 仅回放补齐），
> **漏的是 coverage 这一环**（它绕过了既有出口，直接读了 `attendCount`）；②则是**老数据没重跑**。

### 修了什么
- 新增唯一口径出口 **`common.att_effective(a)`** → `(有效出勤, 仅回放补齐, 看回放总数, 总节数)`；
  `att_stats()` 改为复用它 —— 全流程只此一处定义「算不算上课了」。

- `adapt_legacy.py`（`adapt_api.py` 复用它的构建函数）：快照 `attendance[]` 补

- `report.py`：预警卡学习轴写明「（其中 N 次为看回放补齐）」；**区分「到课」与「只看回放」**——
  对「一次直播都没到、全靠回放」的人，结论写「**未到直播、但已用回放把课补齐**」，

## 版本与口径（v4.17）—— 取 token 改为「账号密码 + 验证码看图」

**用户明确要求沿用这个方式**：「我只给你网址，然后给你账号密码，你发我图形验证码，我解析后发给你验证码，你就登录了，并不复杂。」
所以把 v4.15 立的两条路**整体替换**成这一条主路径，并且**明确取消**此前「绝不向用户索要账号密码」的自设禁令
（该做法**不是**让机器去过验证码 —— 验证码始终由**人**辨认，属于正常的人机协作登录）。

### 现在的第 0 步（只有一条主路径 + 一条折叠兜底）

| | 做法 | 说明 |
|---|---|---|
| **主路径** | 用户给「网址 + 账号密码」 | 浏览器自动化打开登录页并代填账号密码 → **验证码元素截图放大后 `present_files` 给用户** → 用户回 4 位数字 → 代填并提交 → 读 Cookie 的 `token` → 写 `token.txt` |
| 兜底 | 用户自己登录后复制 `token` | 放在手册的 `<details>`「🔧 万一卡住了」里；仅在浏览器工具不可用时才用 |

**仍然保留的一条禁令**：**不要**去调后台 `/login` 接口用账号密码自己登（那才是「让机器过验证码」，不稳定也不该做）。

### 三条铁律（已写进 SKILL.md 第 0 步 + `references/api_contract.md` §1）

1. **不调登录接口** —— 走「浏览器自动化 + 人工看图」；
2. **验证码必须由用户本人辨认**：截图发给用户、**停下等他回复**再填再提交，**绝不自己猜**；
   看不清就让用户回「换一张」，重新截图（失败自愈：验证码错 → 重截；密码错 → 请用户核对；页面变了 → 重新 `snapshot -i`）；
3. **账号密码只用于本次登录**：不写进 `token.txt` / 日志 / 报告 / 中间产物，不回显到对话，用完即弃。

### 为什么这条路更稳（有实测依据）

2026-09-29 的那次后台取数就是这么跑通的（同一台机器、`agent-browser --session`）：
`open` 登录页 → `fill` 账号密码 → `screenshot "img[alt='请输入验证码']"` → 放大 6 倍 → 发给用户 →
用户回 4 位数字 → `fill input[name='logVerify'] <码>` + `eval document.querySelectorAll('form button')[0].click()` →
进后台。整条没人卡住。

而 v4.15 立的「浏览器控制 + 扩展」那条路，卡点在于**要用户先配置**（开关 + 装扩展），
同事实际反馈就是在这里掉队的；`agent-browser` 反倒不需要用户做任何配置。

- **第 0 步只剩一条主路径**：4 步图文 ——（1）说那句话（含账号密码示例）→（2）它自动填好账号密码并把
  **验证码截图发你** →（3）你回 4 位数字 →（4）它自动登录、存好凭证。删掉了原来的「做法一 / 做法二」并列
  与「🔧 说了半天没弹出浏览器？按顺序看这 4 条」。
- 新增折叠块 **「🔧 万一卡住了（验证码看不清 / 它打不开浏览器）」**：① 回「看不清，换一张」；

## 版本与口径（v4.15）—— 取 token 的路径写死为「浏览器登录」

**起因是同事按操作手册使用后的反馈**：
「安装 skill 前的登录没有弹出浏览器，多轮对话后通过接口获取到 token」。

### 为什么改
第 0 步原本只写「用 agent-browser 打开登录页」。但 `agent-browser` 是个**独立的无头 Chromium**
（用户看不到窗口、也不能自己输入），而且本机往往**根本没装**；WorkBuddy 浏览器控制又需要单独开启 ＋ 装扩展。
两条路都不通时，执行方就会自己去找第三条路 —— 去试「账号密码调登录接口」，来回好几轮才勉强拿到 token，
业务同学完全跟不上。

### 现在的取 token 方式（A 不通退 B，B 不通退 C，不要自创第四条）
| | 方式 | 前置 | 说明 |
|---|---|---|---|
| **A** | WorkBuddy 浏览器控制接管**你自己的浏览器** | 开「设置 → Agent → 浏览器控制」＋ 装 WorkBuddy 浏览器扩展 | **首选**；登录页打开后由**用户本人**输账号密码 + 图形验证码 |
| B | `agent-browser` | 本机已装 | 次选；无头浏览器，用户看不到窗口，需用户明确同意由自动化代填。**未装时不要为它去全局 `npm install`**（几百 MB、常失败），直接退 C |
| **C** | 用户自己登录后**复制 token** | 无 | 零依赖兜底，半分钟：`F12` → Console → `document.cookie` → 把 `token=...` **整段粘贴** |

### 两条铁律（已写进 SKILL.md 第 0 步）
1. **token 只能来自「浏览器里真实登录」** —— 不要尝试用账号密码调后台登录接口（图形验证码无法稳定绕过）；
2. **绝不向用户索要账号密码**，也不要让用户把密码贴进对话。

### 顺带加固：`token.txt` 吃下各种粘贴格式
新增 `common.clean_token()`：容忍「裸 token / `token=xxx` / 整段 cookie / `{"token":...}` / 嵌套 JSON /
带引号换行 / 值含 `=` 的 base64」；`load_token()` 在内容明显不对时给出**含两条获取路径**的可照做报错；
`run_all.py` 改为调用 `load_token()` 自检（原先只检查文件是否存在，内容错也照跑）。

📘 `操作手册.html` 第 0 步同步重写：**做法一**（配一次扩展 → 一句话让浏览器打开登录页）/

## 版本与口径（v4.11）

**对接研发封装的「在读学生」接口** —— 课程 / 联席维度加 `--api` 即可：

```
GET /api/ai/getCourseStudents?productName=<课程完整名>     课程维度
GET /api/ai/getCoTeacherStudents?coTeacherName=<联席姓名>   联席维度
```

**实测收益**（同一门课 `2026Q-SX-高二数学清北层日E邵`，新旧链路全量重跑对比）：

| | 旧链路 | 新接口 |
|---|---|---|
| roomId 覆盖率 | 37/58 = 64% | 47/56 = **84%**（加 `--fill` 达 86%） |
| 群数（能拿到聊天） | 31 | **48** |
| 报告主体覆盖学生 | 31 人 | **48 人** |

| 出勤但无沟通 | 23 | **6** |
| 向好转正常 | — | **19 人** |
| 向坏 | — | **0 人** |

联席视角（张巍 81 人）同样：roomId 70/81 = 86%，群 57 → **70**，失联 6 → 7、出勤但无沟通 21 → 10。

**`--fill` 建议常带**：实测接口的「学生课程关系 → 服务群」关联**会漏掉真实存在的群** ——
例：某生的群名写成「高二数学清北层**E邵**」（缺一个「日」字），接口就返回空 roomId，

不覆盖接口值，补全项标 `roomIdSource: "fill_groupname"` 并写进 `snapshot/meta.json` 的 `degraded[]`，可追溯。

**其他要点**：

- 课程名是**精确匹配**，必须传完整全串（旧链路的片段写法不适用）；输入不对会直接报错并提示。

  （课程 58 → 56 人，剔除了已不在读者）。

- **教务维度暂无接口**（`--edu` 不要加 `--api`），仍走旧链路。
- ⚠️ 新接口链路的 `groups[].groupName` 为空串（接口不返回群名）—— 群名本就不参与任何判定
  （报告一律用后台课程名 `productName`）。

## 版本与口径（v4.4）

- **学习分层口径重校 + 新增「学生成绩」为第四类证据（最强证据）**。背景：旧口径下真实数据**所有学生都被判「需重点关注」**，四档退化成一档、徽章失去区分度。改了四处：
  - **③ 老师反馈 → 密度归一化**：旧口径按「指出问题**绝对次数**」扣分（≥3 处即 −2），但真实数学群里老师高强度纠错是**教学常态**（实测三位学生分别在 2/8/8 次课里被指出 11/12/9 处），人人触发、人人扣分。现按「**每 10 轮小黑板**（无小黑板数据时按每 100 条可分析消息）」的指出密度：≥10 → −2、≥5 → −1、未超基线不扣；正面评价 ≥3 → +1~+2。
  - **① 小黑板把「没写完」和「不会」分开**：真实读图里 `未完成收尾` 占错误标注 **25/33** —— 大量轮次是「思路对了但没写完」，属**课堂节奏 / 书写速度**，不再按能力扣分（仅占比 ≥85% 时轻提示 −1）。只有剔除它之后的**实质错误**（计算错误 / 判断错误 / 思路偏差 / 推导跳步 / 漏解…）才按占比扣分（≥30% → −2、≥20% → −1）；「完整作答且无错」≥60% / ≥40% 给 +2 / +1；空白未提交归参与度。
  - **④ 学生成绩（新增 · 最强证据）**：`common.extract_exam()` 从群聊里定期收集的**月考 / 期中成绩**中识别（**只匹配、不生成**）。业务口径：**成绩好（得分率 ≥85%）→ 即使平时作业不做，也属「学习效果较好」→ 档位托底「良好」**；**成绩偏低（<65%）→ 即使作业都交、很配合，也属「学习效果不好」→ 档位封顶「需关注」**；成绩中等 → +1；无成绩 → 0。
    - 保守识别：必须命中考试名关键词（月考/期中/期末/联考/测验…）**且**能归因到本人（句内出现姓名，或分数前不是别人的名字），并排除「满分/总分/卷面」后的数字与「考试范围/时间/报名」事务句；认不出即「未知」，**绝不用裸数字硬凑**。无满分标注时按学科推断（数学 150、其余 100）并注明「按 X 分制推断」。自带 14 条回归用例（含 5 条「应跳过」负例）。
    - 真实数据验证：在 144 人教务存档里**命中 2 例真实成绩**且均逐字核对属实（「老师我们考完月考了 成绩106/120」；「月考141」被老师回复「那9分扣在哪」反证满分 150）。
  - **依据块可核对**：折叠的「学习分层判定依据」现在**逐条给出加减分**，标题给出**累计总分**（成绩托底/封顶时另标「成绩托底 / 成绩封顶」）。
- **实测分布（144 名真实学生，教务视角）**：需重点关注 **8** / 需关注 **73** / 正常 **58** / 良好 **5**（累计分 −4 ~ +4）—— 四档重新有区分度。
- **成绩行**：有成绩时卡片 ① 顶部多一行「成绩：月考 128/150（得分率 85%）· 10-08 ＋ 出处原文」；无成绩时整行不出现。

- **小黑板读图（v3.6 新增，可选）**：加 `--boards <小黑板图片目录>` 后，逐张读取学生课堂手写作答，输出「作答完整度 / 正确错误 / 问题定位 / **关联知识点**」。
  小黑板是判断学生优势与薄弱知识点的**直接依据**，故归入报告第③块「学习掌握与薄弱点」——**结论先行**：先给薄弱知识点与优势，再附小黑板佐证；并与聊天高频话题**交叉验证**（两者都命中标 🖍 双证据）。同时呈现在报告第①块的小黑板佐证里。
  - 目录形如「日期 / 时间戳 / `序号_W或Z-姓名.png`」；**W/Z 只是分批上传标记，不含过关含义**；匹配以**姓名**为准。
  - 全自动读图需配置 OpenAI 兼容多模态模型：写 `<workdir>/boards_llm.json`（`base_url`/`api_key`/`model`）；未配置则生成待填清单，人工回填后再聚合。
  - ⭐ **读图缓存（v4.8 新增 · 增量读图）**：读图是全流程最贵的一步，**同一张图不该读第二次**。
    `board_cache.py sync --boards <小黑板目录> --workdir <工作区> [--batch-size 28]` 会先查本地缓存
    （键＝图片绝对路径，校验位＝文件大小 + mtime）：**命中直接复用**历史结论，**未命中**才进 `board_todo.json` / `board_batches/batch_N.json`；
    读完执行 `board_cache.py merge <result_*.json>` 写回缓存，下一轮自动命中。缓存位 `<skill>/.cache/board_reads.json`
    （**本地文件，含学生姓名，不进 git、不分发**）；图片被替换会自动失效重读。
    典型：某课程 1363 张图中 658 张已读 → 复用后只需读 705 张；下一轮课新增一次课，通常只读几十张。
    ⚠️ 缓存只省「读图」成本，不改「必须全量」的原则：**新图仍要每次课 × 每一轮全读**。
- **只纳入本人负责的群**（v3.4 重要变更）：报告只统计「归本人管理」的班级群——联席看某群是否由你带、教务看某群是否归你管；学生同期报读的其它学科群（由别的联席/教务负责）不纳入。例：数学联席不会再混入该生的物理/化学/英语群。
- **数据以聊天记录为准**（v3.2 / v3.3 重要变更）：
  - 「是否需回复」不再采信后台「是否回复」列，改为识别会话尾部是否仍有未获回应提问。
  - 「响应时效」不再采信后台「超时未回复」列，改为由聊天记录自算（学生提问 → 老师首条回复的最长等待；≥24h 且老师未说明缘由才判迟缓；老师已说明休息 / 放假等则豁免）。
  - 后台监管标记（`isReplied` / `isTimeout`）实测与聊天事实不符，已全部弃用。
- **礼节性消息**：学生/家长的「好的 / 谢谢老师 / 明白了」等收尾语（含表情）识别为无需回复，不计入未闭环、不刷配合度。
- 报告速览卡以「一行信号条」呈现量化风险信号（情绪 / 出勤 / 作业 / 礼貌回应），不堆长文字。
