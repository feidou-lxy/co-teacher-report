# 联席学情报告技能 · co-teacher-report

把企业微信班级群聊天 + 后台课节考勤（＋可选的小黑板手写作答图片读图），一键生成「联席 / 教务 / 课程」三视角学情报告（HTML + 待办 Excel）。

## 一键安装（推荐）

```bash
bash <(curl -sL https://raw.githubusercontent.com/feidou-lxy/co-teacher-report/main/install.sh)
```

脚本会把技能装到 `~/.workbuddy/skills/co-teacher-report/`。
（如需指定其他仓库/分支：`REPO=https://github.com/其他账号/co-teacher-report BRANCH=main bash <(curl -sL <install.sh地址>)`）

## 手动安装

```bash
git clone https://github.com/feidou-lxy/co-teacher-report.git /tmp/co-teacher-report
mkdir -p ~/.workbuddy/skills
rm -rf ~/.workbuddy/skills/co-teacher-report
mv /tmp/co-teacher-report ~/.workbuddy/skills/co-teacher-report
```

## 使用（用你自己的后台账号）

1. 登录 `stadminv2.xqmsx.cn`，从任意请求头取出 `x-token`（JWT，约 24 小时有效）
2. 写入工作目录：
   ```bash
   mkdir -p ~/co-report && echo "粘贴你的x-token" > ~/co-report/token.txt
   ```
3. 生成报告（缺 `openpyxl` 会自动安装）：
   ```bash
   # 联席视角
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --co <联席名> --window 2026-09-01 --month 2026-09
   # 教务视角
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --edu <教务名> --window 2026-09-01 --month 2026-09
   # 课程视角（一门课跨多个联席）；可选带上小黑板图片目录一起分析
   python ~/.workbuddy/skills/co-teacher-report/scripts/run_all.py \
     --course 高二数学211层六C肖 --window 2026-09-01 --boards ~/Desktop/小黑板目录
   ```
4. 产物：`<联席|教务|课程名>_学情分析.html` ＋ `<联席|教务|课程名>_学生待办清单.xlsx`

## 版本与口径（v3.7）

- **三视角**：`--co <联席名>` 联席视角（**联席维度 · 按课程下钻**）；`--edu <教务名>` 教务视角（双维度：按课程 / 按联席下钻）；`--course <课程名>` **课程视角**（**课程维度 · 按联席下钻**，适合「分析某门课下所有学生」）。三种视角共用同一套分析逻辑。
- **职责分工（v3.7 关键口径）**：**联席为学习效果负责** → 看**「联席四维」**＋薄弱知识点/优势，**出勤只作背景**（折叠、不给红黄绿、不参与定档）；**教务为续报负责** → **出勤是核心关切**（完整展开＋红黄绿，异常计入教务定档）＋家长沟通。
  - 「课程-联席」与「联席-课程」两个维度是当前重点：前者＝课程视角按联席下钻（学生卡标所属联席），后者＝联席视角按课程 Tab 切换。
- **联席四维（v3.7 新增）** —— 联席的四个直接抓手，展示在每张学生卡的「① 速览卡」内，并决定「最该盯」的优先级：
  1. **互动状态**：积极 / 一般 / 不积极 / **沉默不回复**
  2. **催交作业 → 是否交**：老师催交后 72h 内学生是否提交（`已提交/催交次数`）
  3. **批改后 → 是否订正**：老师要求订正后 72h 内学生是否改正（`已改正/订正次数`）
  4. **提问意愿**：高 / 中 / 低 / 无
  - **联席 To-Do 严格按四维排序**（互动 → 答疑闭环 → 催交 → 订正 → 提问意愿）；**出勤/请假不再进入联席 To-Do**，避免「确认出勤/补回放」抢走联席的「最该盯」。
  - 若学生**聊天风平浪静但课堂作答多轮未收尾/未提交**，小黑板结论会自动**置顶为「最该盯」**（如「课堂作答 13/29 轮未收尾：课上盯他写完最后一步再交」）。
  - 总览 Excel 同步新增「互动状态 / 催交作业 / 批改订正 / 提问意愿」4 列。
- **小黑板读图（v3.6 新增，可选）**：加 `--boards <小黑板图片目录>` 后，逐张读取学生课堂手写作答，输出「作答完整度 / 正确错误 / 问题定位 / **关联知识点**」。
  小黑板是判断学生优势与薄弱知识点的**直接依据**，故归入报告第③块「学习掌握与薄弱点」——**结论先行**：先给薄弱知识点与优势，再附小黑板佐证；并与聊天高频话题**交叉验证**（两者都命中标 🖍 双证据）。同时进 Excel「小黑板分析(读图)」sheet。
  - 目录形如「日期 / 时间戳 / `序号_W或Z-姓名.png`」；**W/Z 只是分批上传标记，不含过关含义**；匹配以**姓名**为准。
  - 全自动读图需配置 OpenAI 兼容多模态模型：写 `<workdir>/boards_llm.json`（`base_url`/`api_key`/`model`）；未配置则生成待填清单，人工回填后再聚合。
- **只纳入本人负责的群**（v3.4 重要变更）：报告只统计「归本人管理」的班级群——联席看某群是否由你带、教务看某群是否归你管；学生同期报读的其它学科群（由别的联席/教务负责）不纳入。例：数学联席不会再混入该生的物理/化学/英语群。
- **数据以聊天记录为准**（v3.2 / v3.3 重要变更）：
  - 「是否需回复」不再采信后台「是否回复」列，改为识别会话尾部是否仍有未获回应提问。
  - 「响应时效」不再采信后台「超时未回复」列，改为由聊天记录自算（学生提问 → 老师首条回复的最长等待；≥24h 且老师未说明缘由才判迟缓；老师已说明休息 / 放假等则豁免）。
  - 后台监管标记（`isReplied` / `isTimeout`）实测与聊天事实不符，已全部弃用。
- **礼节性消息**：学生/家长的「好的 / 谢谢老师 / 明白了」等收尾语（含表情）识别为无需回复，不计入未闭环、不刷配合度。
- 报告速览卡以「一行信号条」呈现量化风险信号（情绪 / 出勤 / 作业 / 礼貌回应），不堆长文字。
- 详细字段与判定见技能内 `SKILL.md` 与 `references/api_contract.md`。

## 安全提醒

后台「群列表」接口无需 token 也能访问（越权风险）。请**只用自己账号**取 token、**不要外传 token**，也不要查询非本人名下的班级数据。

- 本仓库仅含 `SKILL.md` + `scripts/` + `references/`，**不含任何 token**，可放心公开/转发。
